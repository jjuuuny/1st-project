# 조사 정리 (research-summary)

## 1. 파일 정하기
- 주제별 파일이 있으면 그 파일에 덧붙이고, 없으면 `기획서/<주제>.md`를 새로 만든다.
- 다른 세션이 담당하는 파일(`기획서/세션명령어.md`의 담당 표)은 수정하지 않는다. 그 내용을 반영할 곳은 총괄 문서(`상품기획서.md`, `아침확인.md`)다.

## 2. 파일 형식
- 머리말: 조사일, 조사 방법(어떤 에이전트·세션), 열지 못한 사이트, 표기 기준
- 표기: [확인] / [원문] / [계산] (식 포함) / [해석] / [미확인]
- 신뢰도: 높음(공식·공시·법령 원문) / 중간(언론·판매처) / 낮음(블로그·리뷰·검색 요약)
- 본문: 결과 표 → 요약 지표 → 해석 → 추가로 확인할 것 → 출처 목록 (markdown 링크)
- 지어내지 않는다. 찾지 못한 것은 "찾지 못함"으로 쓴다.

## 3. 대조와 반영
- 기존 문서(`상품기획서.md`, 다른 조사 파일)의 같은 항목과 수치를 대조한다.
- 더 강한 근거(원문, 공시)가 나오면 기존 수치를 고치고, 바꾼 곳에 근거 파일을 적는다.
- 결정에 영향을 주는 발견은 사용자 확인 항목(번호)으로 `아침확인.md` 등에 올린다. 결정 자체를 임의로 바꾸지 않는다.
- `기획서/사용자요청_체크리스트.md`에 관련 요청이 있으면 상태를 갱신한다.

## 4. 마무리
- 커밋하고 main에 push한다 (push 전 `git pull --rebase origin main`).
- 사용자에게 핵심 발견 3~5줄과 결정이 필요한 것만 보고한다.
