# 제품 이미지 레퍼런스 조사 (2026-11-17)

> 계기: 총괄 세션이 만든 제품·배경 프롬프트 결과를 사용자가 반려 → 실제 사례로 다시 잡는다. 배경·세트는 세션 ③ 담당이라 이 문서는 **제품을 어떻게 찍었는가**(각도, 화면 속 크기, 조명, 그림자, 반사, 소품 수)에 집중한다.
> 목적: 베끼기가 아니라 **구조를 배우고 겹침을 피하기**. 이미지 파일은 저장소에 올리지 않고 URL과 설명만 남긴다. 모든 이미지는 각 브랜드 소유이며 참고용이다.
> 조사: 이 세션의 직접 확인(헤드리스 브라우저 화면 캡처, 이미지 열람) + market-researcher 에이전트 3개.
> 표기
> - **[관찰]** 이미지를 직접 열어 본 내용. 크기 비율(%)은 눈 어림값
> - **[문구]** 페이지 텍스트·alt 텍스트에서 확인 (이미지는 못 봄)
> - **[해석]** 추론·의견
> - **[미확인]**
> - 신뢰도: 높음 = 브랜드 공식 사이트·공식 CDN / 중간 = 판매처·언론 / 낮음 = 블로그·커뮤니티

## 3. ChatGPT 이미지 생성: 잘 되는 지시 / 안 되는 지시

근거: OpenAI 개발자 문서·쿡북(열람), OpenAI 커뮤니티(지원팀 답변 포함). help.openai.com·openai.com은 HTTP 403(Cloudflare)으로 열지 못했다. 쿡북·API 문서는 API 기준이라 **ChatGPT 앱과 다를 수 있다.**

| 구분 | 지시 | 근거 | 신뢰도 |
|---|---|---|---|
| ✅ 잘 됨 | **한 번에 한 장, 대상 하나 장면 하나** | 쿡북 예시가 모두 단일 출력 | 높음 |
| ✅ 잘 됨 | 참조 이미지에 번호·역할 지정 ("Image 1: product shape, label, color — keep unchanged") | 쿡북 "Identify each input by number and purpose" | 높음 |
| ✅ 잘 됨 | 이전 결과를 넣고 **한 가지만** 바꾸기, 유지할 것을 다시 적기 | 쿡북 "request one change, and repeat the details to preserve" | 높음 |
| ✅ 잘 됨 | 글자는 따옴표 + "appears once" + "no extra text" | 쿡북 | 높음 |
| ✅ 잘 됨 | 장면 / 대상 / 세부 / 제약 4칸 구조, 제외 목록은 한 줄 ("No watermarks, no logos.") | 쿡북 | 높음 (효과는 미검증) |
| ✅ 잘 됨 | **제품과 배경을 따로 만들어 합성** | 쿡북 "composite the approved edit into the original instead of relying on the prompt" | 높음 |
| ⚠️ 우회 | 3:2 가로(1536×1024)로 받아 **1536×864(16:9)로 자르기** (세로 160px 잘라냄) [계산] | API 기본 크기 3종, 앱에서 16:9 요청 시 3:2로 나왔다는 사용자 보고 | 중간 |
| ❌ 안 됨 | **2×2 그리드·콜라주 한 번 요청** → 한 장으로 취급 | OpenAI 지원팀 답변 (커뮤니티, 2026-05-13): "a single collage, grid … still only counts as one image" | 중간 |
| ❌ 안 됨 | 정확한 16:9 지정 | 2025 사용자 보고 (2026년 성공 보고 1건 있음) | 낮음 |
| ❌ 안 됨 | 같은 대화에서 이어 만들면 **앞 이미지의 배경·스타일이 따라옴** | 커뮤니티·제3자 보고. 앞선 반려 사유("구도가 모두 같다")와 같은 현상 | 낮음~중간 |
| ❓ 불확실 | 긴 규칙 목록 준수, 한글 라벨 철자 | 공식 자료 없음 | - |
| ❓ 불확실 | 무료 한도 | 공식 수치 없음. 제3자 추정 하루 2~3장 | 낮음 |

**운영 원칙 [해석]**
1. 제품 컷은 **새 대화에서 한 장씩**. 배경 컷도 새 대화에서 따로.
2. 제품 모양이 마음에 드는 한 장을 '기준 이미지'로 정하고, 이후 컷은 새 대화 + 기준 이미지 첨부 + "Image 1 = product, keep unchanged; ignore its background".
3. 글자는 넣지 않거나 "ONGYEOL" 한 단어만. 한글·용량은 Figma에서.
4. 하루 한도를 고려해 프롬프트를 먼저 확정하고 생성.

## 4. 우리 제품 컷 구성안 [제안]

전제: 0-1 결정(튜브 크림 100ml, 건성 토너 300ml, 아이보리 + 와인 투톤 무광 불투명, 동백 씨오일 = 잠금, "채우고, 잠그는 장벽", 가을 듀오). 배경 색·세트는 세션 ③ 결과를 따른다.

| # | 컷 | 구도 (사례에서 배운 것) | 겹침 피하기 | 쓰는 곳 |
|---|---|---|---|---|
| 1 | **히어로 단독 — 튜브 세움** | 튜브를 캡이 아래로 세운 정면, 화면 높이 약 60%. 왼쪽 위 광원 + **오른쪽 뒤로 긴 그림자 하나** (D·E). 소품 0 | 아벤느식 흰 배경 정보 컷과 달리 그림자와 투톤 색으로 개성 | 상세페이지 첫 화면, 포트폴리오 표지 |
| 2 | **가을 듀오 — 크림 + 토너** | 같은 바닥선, 토너가 크고 튜브가 작게 (G). 미니 증정은 작은 배지나 옆 미니 튜브 하나 (H) | 토리든식 연회색 무지 대신 세션 ③ 배경 | 상세페이지 구성 안내, 포트폴리오 출시 전략 장 |
| 3 | **텍스처 2단 — '채움 → 잠금'** | 제품 없이 크림 스와치 두 장을 나란히: 왼쪽 촉촉한 덩어리, 오른쪽 얇게 펴진 막 (J를 2장으로 나눔, L의 얕은 초점) | 라운드랩식 '제품 + 분홍 스와치 탑뷰'는 쓰지 않음 | 상세페이지 '2단 텍스처' 설명, 포트폴리오 고객 약속 장 |
| 4 | **원료 — 동백 씨앗 + 오일 한 방울** | 갈라진 씨앗 1~2개 + 오일 한 방울 근접, 흰·중성 배경 (R 형식) | **동백꽃·빨강·분홍·제주 수확 장면 쓰지 않음** (라운드랩·타차와 구분) | 상세페이지 원료 섹션, 포트폴리오 원료 선택 근거 장 |
| 5 | **토너 제형** | 2층 선택 시: 흔들기 전·후 두 장 (불투명 병이면 유리잔·스포이트에 덜어 층을 보여줌). 밀키 선택 시: 화장솜에 적신 흰 유액 근접 | 투명 병 + 위쪽 노란 오일층 히어로는 **달바와 겹침** | 상세페이지 토너 섹션 (0-4 결정 후 확정) |
| 6 | **사용 장면 — 손에 짜는 순간** | 손바닥 위로 튜브를 짜는 근접 (U의 '손 + 도구'를 '손 + 튜브'로) , 옆빛, 얕은 초점 | 얼굴 컷은 실존 인물 문제 때문에 피함. 의사·가운 금지 (화장품법 제13조) | 상세페이지 사용법, 포트폴리오 사용 장면 |
| 7 | **'밤 → 아침' 시간 약속** (선택) | 같은 구도의 튜브 컷 두 장: 저녁 따뜻한 빛 / 아침 차가운 빛 | 사진 연출이며 효능 주장 아님. 문구는 실증 범위 안에서 | 상세페이지 고객 약속, 포트폴리오 차별점 장 |

**추천 우선순위**: 1 → 3 → 4 → 2 → 6 → 5 → 7. 히어로 단독, 2단 텍스처, 씨오일 원료 세 장이 콘셉트("채우고, 잠그는")를 가장 직접 보여준다 [의견].

**만드는 방법 [제안]**
- 1번을 새 대화에서 먼저 확정해 기준 이미지로 쓴다.
- 3·4번은 제품이 없는 컷이라 기준 이미지 없이 새 대화에서 만든다 (배경이 따라오는 문제를 피함).
- 2·6번은 기준 이미지 첨부 + "keep the product unchanged, ignore its background".
- 5번은 0-4 결정 뒤에 만든다.
- 모든 컷: 3:2 가로로 생성 → 16:9 슬라이드는 Figma에서 자른다. 상세페이지(모바일)는 세로 컷이 따로 필요할 수 있다.
