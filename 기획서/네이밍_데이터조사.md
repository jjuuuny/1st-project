## 2. KIPRIS 상표 검색 방법

### 2-1. 접속과 화면 [확인]

- 경로: KIPRIS 메인 > 지식재산정보 검색 > 상표. 직접 URL `https://www.kipris.or.kr/khome/search/searchResult.do?tab=trademark` ([KIPRIS](https://www.kipris.or.kr/khome/main.do), 높음 / 세부 메뉴명은 페이지 요약 조회라 중간)
- 상세검색 필드: 상표명칭(TN, 완전일치 옵션), 유사군(SC), 지정상품(GD), 상품분류(TC), 도형코드(DR), 번호, 출원인·대리인, 날짜 (중간~높음)
- 연산자: `*` AND, `+` OR, `!` 제외, `?` 절단, `^` 근접 (중간)
- '칭호' 전용 필드는 필드 목록에서 확인되지 않음 → 철자 변형을 OR로 묶어 검색 ([help-me.kr KIPRIS 가이드 2026-03-27](https://www.help-me.kr/blog/article/kipris-trademark-search-guide/), 중간)

### 2-2. 화장품 분류 [확인]

| 항목 | 값 | 출처 · 신뢰도 |
|---|---|---|
| 니스 분류 | 제3류 (화장품) | help-me.kr · 중간 |
| 유사군코드 | **G1201** (화장품). 특허청 예시: 화장품 = G1201, S120907, S128302 | [특허청 유사상품 명칭](https://www.kipo.go.kr/ko/similarGoodsNameMng.do?menuCd=SCD0201258&parntMenuCd2=SCD0201114) · 높음 |
| 표기 주의 | 일부 블로그의 'G1201B'는 과거 표기로 보임. 특허청 현행 자료는 G1201 | 블로그 · 낮음 |

### 2-3. 행정상태 읽는 법

| 상태 | 의미 | 출처 · 신뢰도 |
|---|---|---|
| 등록 | 권리 성립. 같은 분야 유사 상표는 거절 사유 | help-me.kr · 중간 |
| 출원 | 심사 중. 먼저 출원된 것이면 뒤 출원을 막을 수 있음 | 같음 |
| 공고 | 이의신청 기간. 이의 없으면 등록 가능성 높음 | 같음 |
| 거절 | 권리 없음 | 같음 |
| 포기 | 권리자가 포기. 충돌 위험 낮음 | 같음 |
| 소멸·무효·취하 | 공식 정의 [미확인] | - |

### 2-4. 사용자 직접 검색용 검색식 [제안]

1. 상표명칭: `온결+ONGYEOL+ONGYEUL+온껼`, 행정상태 **전체**, 유사군 `G1201` → 화장품 분야 충돌 확인
2. 같은 상표명칭으로 유사군 조건 없이 다시 검색 → 다른 류 사용 확인 (인테리어 사례 대응)
3. 추가 후보 각각: `결담+GYEOLDAM`, `스밈+SEUMIM`, `차오름+CHAOREUM`
4. 결과 화면을 날짜와 함께 캡처해 이 문서에 기록

### 2-5. 이번 조사에서 확인 가능했던 결과

| 시도 | 결과 |

- 가장 흔한 구조는 **원료 + 효능**(라운드랩) 또는 **콘셉트 조어 + 성분 + 기능**(토리든)이다. 라인명(콘셉트)과 제품명(성분·효능·제형)을 나누는 방식이 관행이다.
- '수분'은 국내 제품명에 자주 쓰인다 (자작나무 수분, 패리어 수분 크림, 달바 수분보습 컬렉션).
- 표기가 흔들린다: 베리어(에스트라) / 배리어(영문권) / 패리어·배리덤(셀퓨전씨). 쓸 경우 한 가지로 통일해야 한다.
- 숫자(365, 6.0, 1025, 100)의 의미를 공식 설명한 자료는 찾지 못했다 [미확인].
- 장벽 키워드는 에스트라 아토베리어365가 선점하고 있어, 장벽 명시형은 차별화가 어렵다.

## 4. 네이버 데이터랩 검색 지수

### 4-1. 상태

- 이 환경에 네이버 API 키가 설정돼 있지 않아 **"건성 크림, 장벽 크림, 수부지, 속건조, 수부지 세럼" 검색 지수는 조회하지 못했다.**
- 공개 자료에서도 이 5개 키워드의 검색량·지수 수치는 찾지 못했다. 면접 자료에 "수부지 검색량 증가" 같은 문장은 **직접 조회 전까지 쓰지 않는다.**

### 4-2. API 사용법 [확인 — 신규 NAVER API HUB 기준]

| 항목 | 내용 |
|---|---|
| 엔드포인트 | `POST https://naverapihub.apigw.ntruss.com/search-trend/v1/search` |
| 헤더 | `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY`, `Content-Type: application/json` |
| 본문 | `startDate`(2016-01-01부터), `endDate`, `timeUnit`(date/week/month), `keywordGroups`(필수), `device`(pc/mo), `gender`(m/f), `ages`("1"~"11") |
| 연령 코드 | 3: 19~24, 4: 25~29, 5: 30~34, 6: 35~39 (2030 = 3~6) |
| 제한 | 키워드 그룹 최대 5개, 그룹당 키워드 최대 20개 |
| 호출 한도 | HUB 개요: 검색어 트렌드 월 50,000건, 키당 초당 50건. 구 방식은 일 1,000회라는 스니펫이 있으나 원문 미확인 |
| 응답 | `results[].data[]`의 `period`, `ratio` — 조회 기간 내 최댓값 = 100인 **상대값** |

출처: [API HUB 검색어 트렌드](https://api.ncloud-docs.com/docs/naver-api-hub-search-trend), [예시](https://api.ncloud-docs.com/docs/naver-api-hub-search-trend-examples), [HUB 개요](https://api.ncloud-docs.com/docs/naver-api-hub-overview) · 높음 (페이지 요약 조회 기준)

- 구 방식(`openapi.naver.com/v1/datalab/search`, 헤더 `X-Naver-Client-Id/Secret`)은 developers.naver.com 문서가 열리지 않아 원문 확인 못 함. 기존 개발자센터 서비스 종료 일정이 출처마다 다르다 (2026-07 종료 예정 vs 신규 신청 2026-07-31 차단·기존 키 2027-06-30 종료, 후자는 블로그 · 낮음). **신규 키는 NAVER API HUB에서 발급하는 것이 안전하다** [해석].
- 참고: `.claude/settings.json`의 curl 허용은 `openapi.naver.com`만 있다. HUB 엔드포인트(`naverapihub.apigw.ntruss.com`)를 쓰려면 허용 추가와 네트워크 허용 여부 확인이 필요하다 (이번 작업에서 설정 파일은 수정하지 않았다).

### 4-3. 조회 요청안 [제안]

```bash
curl -X POST "https://naverapihub.apigw.ntruss.com/search-trend/v1/search" \
  -H "X-NCP-APIGW-API-KEY-ID: $NAVER_CLIENT_ID" \
  -H "X-NCP-APIGW-API-KEY: $NAVER_CLIENT_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "startDate": "2025-11-01",
    "endDate": "2026-10-31",
    "timeUnit": "month",
    "keywordGroups": [
      {"groupName": "건성 크림", "keywords": ["건성 크림", "건성크림"]},
      {"groupName": "장벽 크림", "keywords": ["장벽 크림", "장벽크림"]},
      {"groupName": "수부지", "keywords": ["수부지"]},
      {"groupName": "속건조", "keywords": ["속건조", "속 건조"]},
      {"groupName": "수부지 세럼", "keywords": ["수부지 세럼", "수부지세럼"]}
    ]
  }'
```

- 1차: 위 요청 (전체 기기·성별·연령)
- 2차: 같은 요청에 `"gender": "f", "ages": ["3","4","5","6"]` 추가 (2030 여성)
- 두 결과는 따로 저장하고 서로 숫자를 직접 비교하지 않는다.

### 4-4. 해석 시 주의점

1. 상대값이다. 같은 요청 안 그룹끼리만 비교한다. 조건이 다른 요청끼리 숫자를 이어 붙이지 않는다.
2. 5개 그룹 중 가장 큰 그룹이 100이 된다. 작은 그룹의 값이 낮다고 검색이 "거의 없다"고 단정하지 않는다.
3. 그룹 안 띄어쓰기 변형의 합산 규칙은 공식 문서에서 확인하지 못했다 → 변형별로 따로 조회해 검증한다.
4. 기간을 바꾸면 최댓값이 바뀌어 같은 키워드라도 값이 달라진다.
5. 성별·연령 조건을 걸면 그 집단 내부 비교일 뿐, 전체 분포로 해석하지 않는다.
6. 절대 검색량이 필요하면 네이버 검색광고 키워드도구(광고 계정 필요)의 월간 검색수를 별도로 확인한다.
