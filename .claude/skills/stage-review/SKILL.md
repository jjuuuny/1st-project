# 단계 검증 (stage-review)

이 프로젝트의 단계를 마무리할 때 아래 순서를 따른다. 규칙은 CLAUDE.md가 우선한다.

## 1. 대상 확인
- 어느 단계인지(1~8) 확인한다. 인자가 없으면 `기획서/상품기획서.md` 0장 진행 상태에서 "진행 중"인 단계를 대상으로 한다.
- 앞 단계가 [확정]이 아니면 진행하지 않고 사용자에게 알린다 (CLAUDE.md 작업 순서).

## 2. 정리 점검
- 결정 항목마다 후보 5개 + 추천안(근거 포함) + [제안] 표시가 있는지 본다.
- 수치마다 출처·신뢰도·[확인]/[계산]/[해석] 표시가 있는지 본다.
- 앞 단계 결정과 충돌하는 내용이 없는지 본다.

## 3. 검증
- `industry-reviewer` 에이전트를 실행한다. 프롬프트에 포함할 것:
  - 검증 대상 단계와 절 번호, 확정된 앞 단계 요약
  - 근거 파일 목록
  - 특히 볼 것: 계산 오류, 근거 왜곡, 앞 단계와의 불일치, 실무 현실성, 빠진 후보, 면접 예상 질문
  - "파일은 수정하지 마"

## 4. 반영
- 지적을 오류 > 불일치 > 근거 부족 > 개선 순으로 처리한다.
- 사실·계산 정정은 바로 반영한다. 결정을 바꿔야 하는 지적은 반영하지 않고 사용자 확인 항목으로 올린다.
- 근거가 부족한 지적(리뷰어의 기억·의견만 있는 것)은 "근거 부족"으로 판정하고 유지한다.

## 5. 기록
- `기획서/상품기획서.md` 7장 "현업 피드백 반영 기록"에 `[리뷰어 N단계] 지적 | 판정 | 반영 위치` 행을 추가한다.
- 사용자 확인이 필요한 항목은 번호를 붙여 `기획서/아침확인.md`(또는 그때의 확인 문서)에 모은다.
- 커밋하고 main에 push한다.

## 6. 보고
- 사용자에게: 바뀐 것, 사용자가 결정할 것(번호), 남은 위험을 짧게 정리한다.
